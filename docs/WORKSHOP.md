# Brain Freeze — Workshop

המשימה והדרישות העסקיות יוצגו במהלך הסדנה.

הקובץ הזה מכיל רק מידע טכני על סביבת העבודה ותהליך העבודה.

---

## סביבת העבודה

עובדים ב:

`apps/web/`

אין לשנות את ה-API.

תיעוד ה-API נמצא ב:

`docs/API.md`

להרצה:

```bash
npm install
npm run dev
```

Frontend:

`http://localhost:5173`

API:

`http://localhost:3001`

---

## לפני שמתחילים

הריצו את:

`inspect-repo`

קראו את הממצאים שלו וודאו שאתם מבינים:

- איפה צריך לעבוד
- אילו דפוסים כבר קיימים
- איך מתקשרים עם ה-API
- אילו מגבלות קיימות בפרויקט
- איך מריצים ובודקים את הפרויקט

לאחר שקיבלתם את דרישות המשימה מהמנחה, השתמשו באייג'נט כדי לנתח ולתכנן את המימוש.

אל תבקשו ממנו להתחיל לממש לפני שעברתם בעצמכם על התכנית.

שמרו את התכנית המוסכמת ב:

`WORKSHOP_PLAN.md`

---

## במהלך העבודה

השתמשו בפידבק אמיתי מהמערכת:

- TypeScript
- build
- תגובות מה-API
- התנהגות בדפדפן
- טסטים

כשמשהו לא עובד, נסו להבין את הסיבה לפני שמבקשים שינוי נוסף.

כשדרישה משתנה, בדקו קודם את ההשפעה שלה על המימוש הקיים ועדכנו את התכנית אם צריך.

---

## בדיקות

לקראת סוף המימוש השתמשו ב:

`add-tests-for-changed-behavior`

עברו על מקרי הבדיקה שהאייג'נט מציע לפני שהוא כותב אותם.

בחרו מספר קטן של טסטים שבודקים התנהגות משמעותית.

להרצה:

```bash
npm run test
```

---

## לפני שמסיימים

הריצו:

```bash
npm run verify
```

לאחר מכן:

1. בדקו ידנית את המסלול המרכזי
2. הריצו `review-before-finish`
3. עברו בעצמכם על הממצאים
4. תקנו בעיות חשובות אם נשאר זמן

---

## סקילים זמינים

תהליכי העבודה נמצאים תחת:

`.agents/workflows/`

בסדנה נשתמש ב:

- `inspect-repo`
- `add-tests-for-changed-behavior`
- `review-before-finish`

לא לכל שלב צריך סקיל.

המטרה היא להשתמש בתהליך עבודה שחוזר על עצמו כשזה מועיל, ולא להפוך את כל המשימה לאוטומציה אחת.
